# 107 버전 개발 노트

## 1. 개발 목표
*   1062 버전의 기능 승계 및 문제점 개선 (핫키, 설정 저장, 창 닫기 문제 해결 완료)
*   새로운 핵심 기능: "GTO-W 감시 모드" 추가
*   사용자 편의성 및 안정성 향상

## 2. 개발 방향 및 의도

### 2.1. "GTO-W 감시 모드" 구현
*   **UI 추가:** 좌 상단 설정 탭에 "모드 선택" 드롭다운 메뉴 추가 (GTO-W 감시 모드 / 방송 진행 모드).
    *   "방송 진행 모드"는 기존 1062 버전의 동작과 동일하게 유지.
    *   "GTO-W 감시 모드" 선택 시, "B" 열(버튼)에 입력된 값들을 기반으로 특정 규칙을 모니터링하는 기능 활성화.
*   **규칙 모니터링 로직 구현:**
    *   `107_Plan.txt`에 명시된 "B" 열의 숫자 규칙들을 코드로 구현.
    *   각 규칙 위반 여부를 실시간으로 감시하고 사용자에게 피드백 제공.
    *   규칙을 모두 통과한 GTO 계획에 대해서는 자동으로 해당 레일의 `<Run>` 버튼이 활성화되도록 구현.
    *   규칙 위반 시, 실행을 방지하고 사용자에게 알림 또는 수정 기회 제공.

### 2.2. 코드 구조 및 유지보수성
*   기존 1062.py 코드를 기반으로 하되, 새로운 기능 추가 시 모듈화 및 함수 분리를 통해 코드의 가독성과 유지보수성을 높일 예정.
*   특히 "규칙 모니터링" 로직은 별도의 함수 또는 클래스로 분리하여 관리 용이성을 확보.

## 3. 초기 개발 단계 계획 (완료 및 진행 중)

1.  **107 폴더로 1062.py 복사:** 1062.py를 107 버전의 기반 코드로 사용하기 위해 `D:\Gemini\107\107.py`로 복사. (완료)
2.  **UI 모드 선택 기능 구현:**
    *   Tkinter 메뉴바에 드롭다운 메뉴 추가. (완료)
    *   모드 선택에 따라 내부 변수(`self.current_mode`)를 변경. (완료)
    *   `current_mode` 값을 `settings.json`에 저장 및 로드 기능 추가. (완료)
3.  **규칙 모니터링 로직 설계 및 구현:**
    *   `B` 열의 데이터를 읽어오는 방식 정의. (완료)
    *   각 규칙을 검사하는 개별 함수 또는 메서드 스케치. (완료)
    *   `check_gto_rules` 메서드에 `107_Plan.txt`의 모든 규칙 검사 로직 구현. (완료)
    *   규칙 통과 시 `<Run>` 버튼 자동 활성화, 위반 시 실행 방지 및 알림 기능 구현. (완료)
    *   **규칙 위반 시 시각적 표시 기능 추가:** 규칙 위반이 발생한 레일의 "B" 열 엔트리 위젯 배경색 변경. (완료)
    *   **GTO 계획 최소 길이 규칙 추가:** GTO 계획 파싱 시 최소 3줄 이상인 계획만 유효하도록 처리. (완료)
    *   **자동 실행 기능 개선:** 규칙 통과 시 GTO 계획이 한 번만 자동 실행되도록 제어. (완료)
    *   **"B" 열 데이터 유효성 검사 강화:** 숫자가 아닌 입력에 대해 경고색 및 메시지 피드백 제공. (완료)

## 5. 고려 사항
*   "2와 1은 반드시 교차해서 등장해야 한다" 규칙에 대한 더 정교한 검증 로직: 현재 GTO 계획의 정의(2로 시작해서 1로 끝나는 단일 시퀀스)와 다른 규칙들을 고려할 때, 현재 구현된 로직이 충분하다고 판단됨. 추가적인 정교화는 사용자님의 구체적인 정의가 필요함.
*   "수정할 수 있는 기회"에 대한 UI/UX 개선.
